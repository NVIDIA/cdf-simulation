# PCB-AOI versioned YAML examples

One versioned YAML per scenario for the `pcb-aoi` domain. Everything here targets
CDF API `1.0.0`. The board-derived coupon USDs used to author these examples
are not distributed in the public DIG 1.2 release. Treat each file as a template:
`scene.usd` is the placeholder `/path/to/your_board.usdc`; replace it, and the
board-specific paths and selectors, before execution. A run that still carries
the placeholder stops with `Cannot open USD file`.
Python scripts that build the same kind of job through `CDFJob` live in
[`../../examples/`](../../examples/README.md).

`cdf/` itself ships no examples: a board, a defect, or a solder solver is PCB-AOI
vocabulary, so the worked examples live with the domain that defines it.

| Example | Purpose |
|---|---|
| `minimal.yaml` | Smallest practical RGB capture with explicit camera geometry. |
| `golden_bottom.yaml` | Bottom-side golden render with dome lighting, no defects, and no sidecar. |
| `scanner_fov.yaml` | Capture stated as the scanner is configured: `fov.scan_area_mm` at `dpi: 600` (or the same pitch as `mm_per_px: 0.042333`), frame size and grid derived, stitched with the image-to-USD sidecar. |
| `scanner_fov_corners.yaml` | The same, with the field of view stated as a test program exports it: `fov.corners_mm`, the lower-left and upper-right corners in world millimetres. The corners size the capture and place it -- here around the J13 header, off the coupon's center. |
| `smt_tombstone.yaml` | YAML equivalent of `tests/functional/test_smt_tombstone.py`. |
| `smt_shift.yaml` | YAML equivalent of `tests/functional/test_smt_shift.py`, including procedural solder. |
| `smt_modus_sideflip.yaml` | YAML equivalent of `tests/functional/test_smt_modus_sideflip.py`: a sideflip rendered under the Modus light, the 2D-dome linear AOI illuminator (`lighting.mode: modus_light`). |
| `smt_surface_evolver.yaml` | SMT solder generated by the Surface Evolver solver (`solver: surface_evolver`); needs the vendored binary, which the container ships. |
| `solder_defects_board.yaml` | Solder-quality defects (`insufficient`, `excess`, `missing_solder`, `dry_contact`) as independent operations; see [Solder defects](../README.md#solder-defects). |
| `tht.yaml` | YAML equivalent of `tests/functional/test_tht.py`, including procedural THT solder. |
| `tht_pin_variation.yaml` | Four-axis THT pin variation on a panelised board with step-and-repeat instances (the pin-variation board). Replace the `<panel>` placeholders with your export. |
| `missing_component.yaml` | Missing-component defect with RGB and semantic output. |
| `local_zip.yaml` | Local ZIP scene containing one root-level USD file. Replace the example archive path and scene root. |
| `s3_usd_input.yaml` | Exact S3 USD input object with a separate S3 output prefix. Replace the example URIs and scene root. |
| `s3_zip_input.yaml` | Exact S3 ZIP input object with a separate S3 output prefix. Replace the example URIs and scene root. |

Validate and inspect the compiled plan without starting Isaac Sim:

```bash
uv run python -m cdf.config pcb_aoi/config/examples/minimal.yaml
```

Run an example with a local Isaac Sim installation:

```bash
export ISAAC_SIM_PATH=/path/to/isaac-sim
uv run python -m cdf.config \
  pcb_aoi/config/examples/golden_bottom.yaml \
  --execute
```

Windows PowerShell:

```powershell
$env:ISAAC_SIM_PATH = "C:\path\to\IsaacSim"
uv run python -m cdf.config `
  pcb_aoi\config\examples\golden_bottom.yaml `
  --execute
```

Run the same versioned YAML through the public release container's `config`
entrypoint, without building the image locally:

```bash
export IMAGE=nvcr.io/nvidia/cdf-simulation:1.2.0
docker pull "$IMAGE"
mkdir -p "$PWD/sdg_test_output/examples"
docker run --rm --gpus all \
  --volume /usr/share/nvidia/nvoptix.bin:/usr/share/nvidia/nvoptix.bin:ro \
  --volume "$PWD/sdg_test_output/examples:/output" \
  "$IMAGE" \
  config pcb_aoi/config/examples/golden_bottom.yaml \
  --execute \
  --output-dir /output/output_dir
```

`scanner_fov.yaml` states the frame in the scanner's own terms. Common AOI line
scanners image at 600 dpi (25.4 mm / 600 px = 0.042333 mm/px) or 1200 dpi
(0.021167 mm/px).
Give `fov.dpi` or `fov.mm_per_px` (one quantity, two spellings) or pin
`fov.image_size_px` and let the dpi follow. `scanner_fov_corners.yaml` gives
the area as two corners (`fov.corners_mm`) instead of a size, which also places
it: the capture is centered on the corners' midpoint, not on the board. The
image is the stated area divided by the pixel pitch, rounded down once, so each
edge sits within half a pixel of its corner. A request the machine cannot make
(300 dpi, or finer than the sensor) still renders and is recorded under
`assumptions` in the compiled plan rather than refused.

The golden and minimal examples do not select components. Defect examples
expect component metadata embedded in the caller-supplied USD or its configured
sidecar.

## Local, S3, and ZIP templates

The three path-focused examples are compileable templates. Replace their
archive paths, S3 URIs, and `scene.root` values before execution. S3 access uses
boto3's standard credential and region provider chain.

In every example, `output_dir` is an ordinary artifact directory or S3 prefix.
The ZIP applies only to the input scene; render results are not packaged into a
ZIP archive.

`local_zip.yaml` expects the archive to contain exactly one root-level `.usd`,
`.usda`, or `.usdc` file. Relative textures and other payloads may remain
inside the archive:

```bash
uv run python -m cdf.config \
  pcb_aoi/config/examples/local_zip.yaml \
  --execute
```

`s3_usd_input.yaml` downloads only the exact `board-a.usdc` object shown in
`scene.usd`; it does not download adjacent objects. `s3_zip_input.yaml`
similarly downloads only `board-a.zip`, then extracts it within the execution
scope:

```bash
uv run python -m cdf.config \
  pcb_aoi/config/examples/s3_zip_input.yaml \
  --execute
```

To load the configuration document itself from S3, upload an example and pass
its URI directly:

```bash
uv run python -m cdf.config \
  s3://pcb-inputs/jobs/job-123/s3_zip_input.yaml \
  --execute
```

## Functional Python counterparts

The Python authoring counterparts are retained as templates. In this public
release they exit with skip status 77 until an approved board fixture is
provided:

- [`../../../tests/functional/test_smt_tombstone.py`](../../../tests/functional/test_smt_tombstone.py)
- [`../../../tests/functional/test_smt_shift.py`](../../../tests/functional/test_smt_shift.py)
- [`../../../tests/functional/test_smt_modus_sideflip.py`](../../../tests/functional/test_smt_modus_sideflip.py)
- [`../../../tests/functional/test_tht.py`](../../../tests/functional/test_tht.py)

The YAML counterparts use the functional CI resolution and sampling overrides
of 640 × 360 and 4 total samples per pixel. Unit parity tests
(`tests/unittests/api_parity/test_job_config_parity.py`) require each of those
YAML files to compile to the same `JobOrderPlan` as its Python counterpart.
